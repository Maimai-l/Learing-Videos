## 解锁图案最复杂能有多复杂（Dr. Zye，SoME1 视频）

"最复杂"的定义：9 个点全用上，8 段连线斜率两两不同（3×3 里正好 8 种斜率）。视频先凑出一个解，再手工穷举出全部 296 个，最后用归纳法给所有 3×奇数 网格造出解。

读了：manim 场景 `zyeworld/youtube/2021/01_patterns/manim/` 全部文件；整片每 5 秒一帧，关键段每 0.5–2 秒一帧。下文代码路径相对 `2021/01_patterns/manim/`。

### 斜率图标：把"斜率两两不同"变成一排可以逐个点亮的格子

- **哪一刻**：2:03 定义复杂度；3:36 起第一次手工尝试；之后 5×5（21:10）、3×5（25:18）的解沿用。
- **画面**：
  - 每种斜率画成"刚好装下它的最小点阵加一条对角线"，比如斜率 1/2 是 3×2 个点加一条角到角的线。图标本身就是解锁网格里的一步。
  - 2:03 并排两个图案：蛇形 1-2-3-6-5-4-7-8-9 和乱画的 1-8-3-6-2-9-4-5-7。每段线复制一份飞到下方，斜率相同的落进同一个图标。左边 8 段只剩 2 个图标，右边剩 7 个。复杂度就是"最后剩几个图标"。
  - 3:36 起 8 个图标排在网格下方。每画一段，对应图标闪一下变黄。
  - 3:54 试画 2→5：新线变红，同时早先画过、同为竖直的 9→6 也变红。观众看到的是"和哪一段撞了"。
- **难点**："斜率两两不同"是全局约束，要把 8 段线两两比较。一团交叉的折线，观众没法判断合不合格。
- **比常规好在哪**：常规做法是给线段标斜率数值或列表，让观众自己比对数字。这里定义第一次出现就被演出来（2 个图标对 7 个），冲突时把撞车的旧线段一起标红，死路的原因直接画在图案上。后面更大的网格沿用同一套图标，不用重新学怎么读图。
- **证据**：
  - `chapter_1to3.py:52-68` `SlopeGroup`：图标是 (w+1)×(h+1) 的点阵加一条线。
  - `chapter_1to3.py:233-290` `Pattern3`：左边 8 段线 `FadeTransform` 到只有两个目标的 `slope_list1[0]`、`slope_list1[1]`。
  - `chapter_1to3.py:596-625`：死路演示，新线 `color=RED`，旧线 `lines[4].animate.set_color(RED)`。
  - 截帧：`lock-0211.jpg`（2 个图标对 7 个）、`lock-0354.jpg`（两段竖线同时变红）、`lock-0452.jpg`（8 个全黄）。

### 斜率位置小图：把"这一步只能这样走"摊开给人看

- **哪一刻**：6:18 出题（Try It Yourself #2，给定 1→2，不靠试错找到解），6:40–7:24 解答，7:28 写成流程图。
- **画面**：网格右侧是 8 个斜率图标。点亮一个斜率（比如 −2），网格下方弹出几张缩小的 3×3，每张画着这个斜率在网格里的一种放法（1→8、2→9）。碰到已用点的那张变红，主网格上同时闪出那条红线；唯一剩下的那张变黄，主网格画出它。之后每一步同样五拍：点亮斜率、弹出全部放法、可行的变黄、画线、小图消失，节奏越来越快。竖线一次弹出 9 张。
- **难点**：穷举 296 个解靠的是"某个斜率只剩一个位置，所以现在必须用它"。口述时观众得在脑子里列全一个斜率的所有位置，再逐个排除，做不到。
- **比常规好在哪**：常规讲回溯会画搜索树，或在一个网格上"试、退、再试"。搜索树说明了在穷举，说明不了这一步为什么只能这样走。小图按斜率列出全部放法，画的是剪枝的理由。出题时特意选了每一步都只有一种走法的局面，观众先自己碰到"被迫"，流程图只是把这个体验写成规则；到 8:00 宣布 296 个时，观众知道这个数怎么来。
- **证据**：
  - `chapter_1to3.py:71-95` `Minigrids`：枚举一个斜率及其整数倍在 3×3 里的全部放法，每种画成缩小 0.4 倍的网格。
  - `chapter_1to3.py:676-769` `Scene6`：`minigrid_ans = [None, None, 0, 0, 1, 5, 0, 0]` 记每一步唯一可行的是第几张；`step()`（707-728 行）固定五拍。
  - 原文 6:27："There is only one solution to this problem, and there is only one logical path to take in each step."
  - 截帧：`lock-0650.jpg`（1→8 那张和主网格上的红线）、`lock-0718.jpg`（竖线的 9 种放法）。

### 归纳构造：按斜率族拆成四个彩色图层，每层往外多套一圈

- **哪一刻**：22:48 说明种子就是 4:43 那个"just trial and error"找到的第一个解；24:15 提示卡；24:45–25:30 无旁白的图解；25:58 揭示分组。
- **画面**：3×3 的解按斜率族拆成四层：红色 X、橙色小 X、黄色 V、绿色一竖一横。提示卡只画出红 X 从 3×3 到 3×5 变成两层同心的 X，橙和黄画成"?"留给观众。之后每层单独演示 3→5→7，每次往外多套一对更平的交叉线或更宽的 V。四层在透视里汇合成原解，再在 3×5 上汇合，按路径顺序描一遍，上下两排斜率图标逐个点亮。最后左边列出 3×5 的全部斜率，按 ±1/偶数、±1/奇数、±2/奇数、0 和 ∞ 分四行，右边是对应颜色的四层。
- **难点**：3×(2k+1) 的解是 6k+2 段交错的折线，看不出下一个网格的解长什么样。网格加宽两列时，新增的斜率正好落在这四族里。
- **比常规好在哪**：常规要么直接给公式（第 i 步连哪两个点），要么摆出 3×3、3×5、3×7 三个完整的解让观众找规律，叠在一起只是一团线。这里分层的依据就是复杂度的定义（斜率），拆法本身就是证明思路。种子选片头随手凑出的解，片尾的归纳从片头接上。
- **证据**：
  - `induction.py:7-36`：四层的生成函数 `subp1`–`subp4`，参数 k 是网格宽度，每层一个 for 循环往外加线。
  - `induction.py:40-59`：四层分别着 RED/ORANGE/YELLOW/GREEN，沿 z 方向错开后用 `move_camera` 转到透视。
  - `induction.py:125-203` `Induct4_5`：3×5 时四层汇合，按路径顺序描线并点亮图标。
  - 原文 24:15："divide this pattern into a few parts, Extend them individually, And add all the parts again to make a 3 by 5 pattern."
  - 截帧：`lock-2436.jpg`（提示卡）、`lock-2449.jpg`（红 X 3→5→7）、`lock-2605.jpg`（斜率分组和四层并排）。
