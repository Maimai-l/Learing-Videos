# 问题与避免方法

## 一、理解需求

| 问题 | 避免方法 |
|---|---|
| 没有先想清楚“怎样让观众理解”这个科普目标，而是顺着你的话改 | 先用文字把概念讲给一个没接触过的读者，能讲清楚了，再写脚本 |
| 把脚本理解成先给结论，提出“开头直接摆出代价”“先给最终画面” | 脚本讲的是经过，理解在过程中产生，结论不在开头说出（就像讲丑小鸭的故事，不会先说“不要以貌取人”） |
| 把“不要猜谜、不要转折”理解成连动机都不要，写成了教科书的推导顺序 | 从具体情境和真实问题出发，让每一步自然引出下一步 |
| 只知道 3b1b 的表面特征（角色、口号），没有理解它怎样讲解 | 关注讲解本身：从具体问题出发，把推导做成可以看见的过程 |

## 二、讲解与推导

| 问题 | 避免方法 |
|---|---|
| 只有结论和计算，没有推导，难点没有正面处理 | 找出真正的难点，写出完整推导 |
| 把非显然的结论当作显然，例如“平均值的标准差是 σ/√n”“x̄ 让平方和最小” | 站在没学过的读者的角度检查每一句；不显然的都要推出来 |
| 用两个求和号代替推导 | 推导要逐步写，先算 n = 2 的小例子，再推广，每一步都说明理由 |
| 用到一个概念却不解释，例如误差平方的期望为什么是 σ² 而不是 0 | 在第一次用到时说明 |
| 直接写出 z，读者对标准化没有预期 | 先写正态分布标准化的一般形式，再把推出来的量代进去 |
| 1.96 先出现，再说“这是标准正态分布的性质”，这句话没有解释任何东西 | 先约定 5% 这个标准，再由 5% 推出 1.96 |
| 解释放错位置，例如第四步的解释放在第五步之后 | 解释紧跟在它所解释的内容后面 |
| 凭空做对比，例如“而不是 (nσ)²”，读者本来就没有这个预期 | 不制造读者没有的预期 |
| 思路断裂，读者跟不上（3.1 节） | 先说目的，再用具体数据演示，最后给一般推导 |
| 用 n 维向量和投影来讲，抽象难懂，动画也难以表现 | 用数轴、间距、两个数据的例子讲 |

## 三、语言

| 问题 | 避免方法 |
|---|---|
| 比喻过多，不符合中文语感，搭配不当 | 少用比喻；确有必要时，用“就像”“类似”标明是在打比方 |
| 元话语，例如“先约定记号”“到这里没有任何困难”“第二部分回答第一个问题”“由第一条” | 删去，直接讲内容 |
| 句子生硬、过短，缺少连接 | 写完整、通顺的句子，补上主语和连接词 |
| 用角色对话（小 σ）来制造吸引力，显得尴尬 | 去掉角色，靠内容本身推进 |

## 四、审稿流程

| 问题 | 避免方法 |
|---|---|
| 审稿 prompt 一开始没有给出中文规范的依据 | 写明规范：吕叔湘、朱德熙《语法修辞讲话》，黄伯荣、廖序东《现代汉语》，《现代汉语词典》第 7 版，余光中《怎样改进英式中文》，思果《翻译研究》 |
| prompt 里写角色设定（“你是一位资深编辑”）和工具用法说明，没有用 | 直接写要求：旁白不生硬，语法符合中文语感和表达规范 |
| 审稿标准只有“不许做什么”，每轮只删不补，没有检查读者能否理解 | 加上一条：每一步推导，没学过的读者能否跟上 |

## 五、素材

| 问题 | 避免方法 |
|---|---|
| 列出的素材只是想到的默认来源，没有看过图，也没有核对是否适合脚本 | 只列真正打开、核对过的素材；这部视频以代码绘制的可视化为主，图片只作举例 |

## 六、工作方式

| 问题 | 避免方法 |
|---|---|
| 在回复里重复输出文件内容，浪费 token | 长内容只给文件，回复只说明改了什么 |
| 用文档工具写稿 | 稿件用 md 文件 |
